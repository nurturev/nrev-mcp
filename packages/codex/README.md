# nrev-workflows — Codex CLI / Codex app package

Generated by `scripts/sync-agents.sh` from the canonical `shared/`. Do not edit
`skills/`, `mcp/`, or `AGENTS.md` here — edit `shared/` and re-run the sync.

Contents:
- `.codex-plugin/plugin.json` — native Codex plugin manifest (Codex ≥ 0.117)
- `.mcp.json` — MCP server declaration (relative `command` + `cwd`, resolved
  against the plugin root)
- `bin/run-mcp.sh` — launcher (finds `uv`, picks repo source or bundled `mcp/`)
- `skills/` — the 10 nRev domain skills (open Agent Skills format, auto-loaded)
- `mcp/` — the bundled MCP server (stdio, launched via `uv`)
- `AGENTS.md` — always-on context (Codex reads `AGENTS.md` natively)
- `config.toml` — MCP config block for a manual, no-plugin install

Prereqs: Python 3.10+ and [uv](https://docs.astral.sh/uv/).

## Install — Option A: Codex plugin (recommended)

```
codex plugin marketplace add https://github.com/nurturev/nrev-mcp.git
codex plugin add nrev-workflows@nrev
```

(Or browse `/plugins` in the TUI / the Codex app's plugin settings — the
marketplace manifest lives at `.agents/plugins/marketplace.json` in the repo
root and points at this package.)

The plugin registers both the skills and the MCP server. Start Codex; `/mcp`
should list `nrev-workflows`. Ask it to "log in to nrev workflows" (the
`auth_login` tool) — a browser opens for sign-in once.

## Install — Option B: manual (no plugin)

1. **Skills** — Codex auto-discovers any `SKILL.md` under `~/.agents/skills/`
   (user scope) or `.agents/skills/` (repo scope):
   ```
   mkdir -p ~/.agents/skills
   cp -R skills/* ~/.agents/skills/         # or symlink for a dev loop
   ```
2. **MCP server** — append the block in [`config.toml`](./config.toml) to
   `~/.codex/config.toml`, setting the absolute path to this package's
   `bin/run-mcp.sh`.

## How the server launches (verified against Codex source + a live install)

- Codex runs MCP servers **outside** its sandbox — full network and filesystem
  access. The first launch cold-resolves dependencies with `uv`; its only
  budget is `startup_timeout_sec` (30s default in current Codex, 10s in older
  builds — the plugin and config block set it explicitly).
- Codex forwards a **minimal environment** (PATH, HOME + a small whitelist).
  `bin/run-mcp.sh` prepends the common uv install locations because the
  desktop app's own PATH may not include them. Anything else (e.g.
  `NREV_ENV`) must be passed via the server's `env` map.
- Codex does **not** expand `${CLAUDE_PLUGIN_ROOT}`-style variables in MCP
  configs — `.mcp.json` therefore uses a relative `command` plus `cwd`, which
  Codex resolves against the plugin root (same pattern as OpenAI's own
  plugins).

## Auth & environment

Sign-in is shared with every other agent: the session lives in
`~/.nrev-workflows/credentials` and auto-refreshes. `NREV_ENV=staging` switches
environments (add it under `env` in the MCP server config).
