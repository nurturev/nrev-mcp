# nrev-workflows — Gemini CLI extension

Generated by `scripts/sync-agents.sh` from the canonical `shared/`. Do not edit
`skills/`, `mcp/`, or `GEMINI.md` here — edit `shared/` and re-run the sync.

Contents:
- `skills/` — the 10 nRev domain skills (open Agent Skills format, auto-loaded)
- `mcp/` — the bundled MCP server (stdio, launched via `uv`)
- `GEMINI.md` — always-on context (the extension's `contextFileName`)
- `gemini-extension.json` — extension manifest (MCP server + context file)

Prereqs: Python 3.10+ and [uv](https://docs.astral.sh/uv/) on `PATH`.

## Install

From a local checkout (works with a monorepo subdirectory):

```
gemini extensions install ./packages/gemini
```

Gemini copies the extension into `~/.gemini/extensions/nrev-workflows/`, reads
`mcpServers` from the manifest, and auto-discovers `skills/` from the installed
extension dir. Then pre-warm the server once to avoid a first-run timeout while
uv resolves dependencies:

```
uv run --quiet --project ~/.gemini/extensions/nrev-workflows/mcp nrev-workflows-mcp
```

Restart Gemini CLI; `/mcp` should list `nrev-workflows`. Ask it to "log in to
nrev workflows" (the `auth_login` tool) — a browser opens for sign-in once.

> ⚠ **Verify before relying on remote install.** `gemini extensions install
> <git-url>` historically expects the manifest at the repo root. Installing this
> subdirectory of the monorepo may require the local-path form above, a `--ref`/
> path flag, or a small published satellite repo. The `${extensionPath}` MCP
> path variable is also version-specific. Both are called out in the design
> doc's "Open items" — smoke-test against a live Gemini CLI before distributing.

## Auth & environment

Sign-in is shared with every other agent: the session lives in
`~/.nrev-workflows/credentials` and auto-refreshes. Set `NREV_ENV=staging` in
the manifest's server `env` map to switch environments.
